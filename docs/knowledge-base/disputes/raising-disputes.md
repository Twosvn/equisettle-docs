# Raising & Managing Disputes

When a customer disagrees with an invoice, case, or charges, you can raise a formal dispute. Disputes are tracked through a defined lifecycle with priority levels, evidence, and resolution options.

## What is a dispute?

A dispute is a formal record that a customer is contesting something — an invoice amount, a charge, a case, or a sales order. It's tracked separately from the case or invoice it relates to, with its own status, priority, and resolution process.

Disputes can result in:
- **Credit notes** — adjustments to the amount owed
- **Invoice corrections** — updated invoice with correct details
- **Rejection** — dispute found to be invalid, no changes made
- **Case adjustments** — changes to the case based on the dispute outcome

## Creating a dispute

To raise a dispute:

1. Choose what the dispute is **about**: an invoice, a case, or a sales order
2. Set the **priority**:
   - **Low** — minor issue, not time-sensitive
   - **Medium** — needs attention but not urgent
   - **High** — significant issue requiring prompt resolution
   - **Urgent** — critical issue, immediate action needed
3. Set the **severity**:
   - **Minor** — small impact
   - **Major** — significant impact on the customer or balance
   - **Critical** — major financial or relationship impact
4. Add a **description** explaining the dispute
5. Attach **evidence** — up to 10 files (documents, emails, screenshots, etc.)

## Dispute lifecycle

Disputes follow a defined progression:

```
Pending Admin Review → Under Admin Review → In Progress → Resolved / Rejected → Closed
```

| Status | What it means |
|--------|--------------|
| **Pending admin review** | Submitted and waiting for an admin to pick it up |
| **Under admin review** | An admin is investigating the dispute |
| **In progress** | Actively being worked on — may involve communication with the customer |
| **Resolved** | The dispute has been settled (credit note issued, adjustment made, etc.) |
| **Rejected** | The dispute was reviewed and found to be invalid — no changes made |
| **Closed** | The dispute is fully finished — no further action needed |

## Working on disputes

| Action | What it does |
|--------|-------------|
| **Activate** | Move from "pending admin review" to "under admin review" — starts the investigation |
| **Approve** | Accept the customer's dispute claim |
| **Resolve** | Mark as resolved — record the outcome and any adjustments made |
| **Reject** | Mark as invalid — explain why the dispute was not upheld |
| **Close** | Finalise the dispute — no more actions will be taken |
| **Unlink** | Remove the dispute's association from a case (the dispute record is kept) |

## Evidence and attachments

Each dispute can have up to **10 file attachments**:

- Supporting documents (contracts, agreements, correspondence)
- Screenshots
- Emails
- Any other evidence relevant to the dispute

Each attachment is tracked with:
- Filename
- File size
- Upload date
- File type

## Credit note resolution

When a dispute is upheld and the customer is owed an adjustment:

1. A **credit note** is issued against the original invoice
2. The credit note is linked to both the dispute and the invoice
3. The invoice's outstanding balance is **adjusted** accordingly
4. The change is tracked in accounts payable

Credit notes provide a proper financial record of the adjustment rather than just changing the invoice amount directly.

## Dispute analytics

Track your dispute handling performance:

| Metric | What it shows |
|--------|-------------|
| **Total disputes** | How many disputes have been raised |
| **Status distribution** | Breakdown by current status (pending, in progress, resolved, etc.) |
| **Average resolution time** | How long disputes typically take to resolve |
| **Admin review metrics** | How quickly disputes are picked up and processed |

## SLA tracking

For each dispute, the platform tracks:

- **Response times** — how quickly the dispute was acknowledged and acted on
- **Breach detection** — flags disputes that have been open longer than expected
- **Timeline** — a complete history of every status change, action, and note

The timeline includes: stage, status, who made the change, their role, and any notes. This provides full accountability for dispute handling.

## Good to know

- Disputes are tracked separately from cases — they have their own lifecycle and status
- A dispute doesn't automatically change the invoice or case — changes happen through the resolution process
- All dispute activity is recorded for audit purposes
- Dispute analytics help you identify patterns — if many disputes relate to the same issue, it may indicate a broader problem
- Resolving a dispute with a credit note creates a proper financial record, not just a balance adjustment
